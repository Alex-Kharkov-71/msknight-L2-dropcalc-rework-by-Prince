# DropCalc для PHP 8 и L2JMobius (HighFive) — ветка `php8-l2jmobius`

Это порт Michelle Knight's Drop Calc на **PHP 8** и сервер **L2JMobius CT 2.6 HighFive**.
`main` — исходная версия, эта ветка от неё не зависит и ничего в ней не меняет.
**Ставьте сначала на тестовый сервер.** Многие GM-инструменты пишут прямо в базу игры.

## Что нужно

- PHP 8.1+ с расширениями `mysqli`, `xml` (SimpleXML), `gd`, `mbstring`
- MariaDB/MySQL, базы игры и логина (как у вас сейчас)
- Датапак L2JMobius (папка `data` рядом с серверными файлами)

## Установка на тест

1. Скопируйте файлы ветки на веб-сервер.
2. Скопируйте `config.php.example` в `config.php` (он в `.gitignore`) и заполните `$gameservers` и `$dblog_*`.
   Описание всех позиций массива сервера — в комментарии над ним. **Путь к файлам сервера
   (позиция 6) должен заканчиваться на `/`** и указывать на папку, внутри которой лежит `data/`
   (в сборке Mobius это `.../dist/game/`). Поля telnet (9–12) для Mobius оставьте пустыми.
   Если часовой пояс не тот — раскомментируйте `date_default_timezone_set(...)`.
   Новые настройки добавляются в `config.php.example` — переносите их в свой `config.php`.
3. **Установка таблиц — из самого DropCalc.** В `config.php` впишите свой игровой аккаунт в `$install_admins`
   (например `$install_admins = array("wolf");`), откройте сайт, войдите этим аккаунтом (пароль берётся из `accounts`
   логин-сервера) и нажмите ссылку **[ Install DropCalc tables ]** под шапкой страницы (или откройте `install.php`).
   Даже на пустых базах страница входа открывается без ошибок; пока таблиц нет, на ней написано, что DropCalc
   ещё не настроен.

   На странице установки — все базы по очереди: **логин-БД** и каждый сервер из `$gameservers`, у каждой своё
   состояние (`not installed` / `partly installed` / `installed`) и кнопки:
   - **Install tables** (или *Install missing tables*) — создаёт недостающее; у полностью установленной базы кнопка
     неактивна;
   - **Recreate from scratch** — только при установленных таблицах: нужно поставить галочку «yes, delete and
     recreate» и подтвердить предупреждение браузера. Это удаляет **все данные DropCalc** в этой базе (настройки,
     импортированные данные, список доверенных, статистику; для логин-БД — пользователей). Затрагиваются только
     таблицы `knight*`, игровые таблицы не трогаются.

   Первым ставьте первый сервер из списка: его база хранит и общие настройки интерфейса для всех серверов.
   Пользователю БД из `config.php` нужны права `CREATE` (и `DROP` для пересоздания).

   Что получится в базах: в игровой — все таблицы `knight*` и одна строка `knightsettings` со **стартовыми
   безопасными настройками**: пороги `sec_inc_gmlevel = sec_inc_admin = 256`, то есть никто не GM и не админ (в
   схеме по умолчанию 0 — при нуле любой игрок прошёл бы как админ), регистрация через веб и гости выключены,
   рейды `drop_chance_*` = 1.00. В логин-БД — `knightdrop` с обычным пользователем на **каждый существующий**
   аккаунт логин-сервера (новые появляются при первом входе в DropCalc).

   Те же скрипты можно выполнить вручную: `mysql ... < sql/install_game_db.sql` (в каждую игровую БД) и
   `sql/install_login_db.sql` (в БД логина).

   **Как работает доступ.** Отдельной роли «админ DropCalc» нет: уровень = `accounts.accessLevel` игрового аккаунта,
   и учитывается он только если запись в `knightdrop` **верифицирована** (`verified = 1`), иначе уровень считается 0.
   Поле `knightdrop.access_level` — копия `accounts.accessLevel`; при расхождении вход идёт как гость, поэтому
   одним `UPDATE knightdrop` админа не сделать. Список `$install_admins` даёт право только на страницу установки.

   **Первый админ** — `sql/make_admin.sql` (подставьте логин): шаг 1 в БД логина верифицирует аккаунт, шаг 2 в игровой
   БД задаёт пороги (`sec_inc_admin` = accessLevel вашего админа). Админами станут все верифицированные аккаунты с
   уровнем не ниже порога, остальные игроки остаются обычными. Если у аккаунта `accessLevel = 0`, поднять его
   придётся в `accounts`, и человек станет GM и в самой игре. После настройки админов `$install_admins` можно очистить.
   База `knight_db` из позиции 8 массива сервера (`itemlog`, `accnotes`...) отдельной установки не требует.
4. Войдите администратором → **Server Utilities** → по очереди **Import**:
   предметы, NPC (вместе с дропом и скиллами NPC), скиллы, рецепты, магазины, спавны.
   Предметы и NPC идут по файлам диапазонов (`00000-00099.xml` …) с автообновлением окна —
   на полном датапаке это занимает время, окно закрывать нельзя.

## Что изменилось по сравнению с оригиналом

| Было (старый l2jserver) | Стало (L2JMobius) |
|---|---|
| `mysql_*` | слой совместимости `mysql_compat.php` поверх `mysqli` (≈3600 вызовов не переписывались) |
| `npc`, `droplist`, `armor`, `weapon`, `etcitem` в БД сервера | XML датапака → `knightnpc`, `knightdroplist`, `knightweapon`, `knightarmour`, `knightetcitem` |
| `merchant_buylists`, `merchant_shopids` | `knightbuylist` (shop_id = id NPC; цена `NULL` = цена предмета) |
| `spawnlist` (точка) | `knightspawnlist` + `knightspawnzone` — в датапаке спавн это **полигон зоны**, на карте он рисуется контуром |
| `class_list` | `knightclass` (с расовыми префиксами `H_`, `E_`, `DE_`, `O_`, `D_`, `K_`, как в старой таблице) |
| `skill_trees` (макс. уровень скилла) | `knightskills.levels` из атрибута `levels` |
| `npcskills` | `knightnpcskills` из `<skillList>` |

Дроп в новом формате двухступенчатый: шанс группы × относительный шанс предмета внутри группы.
Страницы показывают итоговый процент: `шанс_группы × шанс_предмета / 100`.

Не менялись и продолжают читать **живую** БД игры (проверено по вашей схеме):
`characters`, `clan_data`, `castle`, `clanhall`, `heroes`, `pets`, `items`, `raidboss_spawnlist`,
`grandboss_data`, `random_spawn`, `random_spawn_loc` и др.

## Telnet и лампочки «сервер онлайн»

У L2JMobius нет telnet-консоли. Лампочки в шапке (логин-сервер и игровые серверы) — это обычное TCP-подключение
к порту, telnet им не нужен; хост берётся из позиции 13 массива сервера (иначе 9, иначе хост БД), порт —
позиция 7 (игровой) и `$dblog_port` (логин), ожидание — `$status_timeout` (по умолчанию 2 с, раньше 10 с на
каждый лежащий сервер при каждой загрузке страницы).

Все действия через telnet (kick, ban-kick, announce, msg, gmchat, jail, give, restart, логин-сервер) при
`$telnet_enabled = false` (по умолчанию) отказывают **сразу** с сообщением «Couldn't connect to telnet», без
ожидания таймаута и без фатальных ошибок. Часть таких страниц до этого ещё и записывает изменения в БД
(например, бан аккаунта) — это продолжает работать, но без мгновенного кика из игры.

## Чего больше нет (и почему)

- **День/ночь у спавнов** — в датапаке такого атрибута нет, всё считается постоянным спавном.
- **Точные точки спавна** — только зона (полигон). Исключение: рейд- и гранд-боссы, у них точка из БД.
- **Миньоны боссов** — таблицы `minions` в Mobius нет.
- **Районы магазинов** — таблиц `zone`/`teleport` нет; район определяется как ближайшая запись из
  `knightloc` (названия и координаты городов нужно внести вручную, как и раньше).
- **Зоны на статистике** — читаются из `data/zones/zone.xml` старого формата; в Mobius файла нет,
  список просто пуст.
- **GM-инструменты, зависящие от исчезнувших структур, отключены** с понятным сообщением:
  создание NPC (`npccreate`), выдача GM (`givegm`), права команд (`settings4`), статы питомцев
  (`givepskill`), наборы брони и питомцы в `giveitem`, дерево скиллов класса в `skills-change`,
  Varka/Ketra в `char-change`, оффлайн-разджейл (`jail`), правка дропа (`drops.php`) и магазинов
  (`shops.php` — только просмотр). Дроп и магазины в Mobius живут в XML, править их через БД нечего.

## Что проверено, а что нет

Проверено автоматически на PHP 8.3 + MariaDB, **на ваших реальных схемах** обеих баз:

- все 103 страницы открываются без фатальных ошибок PHP (`E_ALL`);
- импортёры отрабатывают на ваших XML-образцах (в таблицы с реальной структурой, включая `enum`);
- содержимое страниц сверено с исходными XML (шанс дропа Adena = 70, количество 30/42,
  цена в магазине, район магазина, имя класса, контур зоны на карте);
- все SQL-запросы по колонкам сверены со схемой `characters`, `items`, `castle` и др.

**Не проверено:** работа с настоящими данными вашего сервера, telnet-команды GM-инструментов,
рейд-боссы/минионы (не было образцов), многофайловые диапазоны полного датапака,
нагрузка. Спавны без `territory` (точечные, например у торговцев в городах) импортёр пока **не читает** —
нужен образец такого файла.
